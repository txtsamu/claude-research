# Immich fork: Effect v4 rewrite, stage 1 (repositories)

Goal: rewrite the AI-free Immich server fork (`~/immich`, branch `strip-ai`, see [immich-strip-ai-machine-learning-fork.md](immich-strip-ai-machine-learning-fork.md)) onto Effect v4, **without** changing the generated OpenAPI spec. Work is on branch `effect-v4` (off `strip-ai`), uncommitted at the time of writing apart from the subtree commit.

## Decisions

- **Incremental, not a rewrite of the framework.** Server is ~50k non-spec lines on NestJS 12 + Kysely + BullMQ + socket.io with 158 spec files; every service extends `BaseService` and gets all 57 repositories via a positional constructor. Replacing Nest with Effect `HttpApi` would change the OpenAPI output the web app/SDK/mobile client are generated from, so controllers stay on Nest; repositories and services are converted stage by stage.
- **Effect v4 is stable.** `npm view effect dist-tags` showed `latest: 4.0.5` (4.0.0 stable shipped about 2026-10-01; `beta`/`rc` are separate tags). The `effect/unstable/*` prefix is gone in stable, and `@effect/platform`, `@effect/sql`, `@effect/rpc` etc. are merged into `effect`. Service definition is `Context.Service` (the beta's `ServiceMap.Service` was renamed). Vendored `main` can be ahead of 4.0.5, so check `server/node_modules/effect/dist/*.d.ts` when an API from `repos/effect` is missing.
- **Kysely stays.** The `.sql` docs (`server/src/queries`) are generated by running repository methods through Kysely logging. Effect only wraps execution and typed errors.
- **No codemod exists** for async/await/NestJS to Effect (searched); the work is manual, parallelised with subagents.

## Steps (in order)

1. Vendor Effect source for agents ("git subtree trick"). Fedora ships `git subtree` as a separate package:
   ```bash
   sudo dnf install -y git-subtree
   cd ~/immich
   git subtree add --prefix=repos/effect https://github.com/Effect-TS/effect.git main --squash   # 56 MB, 1 commit
   ```
   Then: `AGENTS.md` (read `repos/effect/LLMS.md` first, `repos/` is read-only, never import from it, AI features must stay removed, OpenAPI spec must stay identical, how to `git subtree pull`), `CLAUDE.md` (`@AGENTS.md` + "use subagents whenever possible, disjoint files each"), `.vscode/settings.json` excludes for `repos/**`, `repos/` in `.dockerignore`. `pnpm-workspace.yaml` globs do not include `repos/`, so it does not join the workspace.
2. `git checkout -b effect-v4`; `cd server && pnpm add effect@4.0.5`.
3. Bridge helpers in `server/src/effect/`: `errors.ts` (`Data.TaggedError` classes carrying `cause: unknown`: `DatabaseError`, `FileSystemError`, `LibraryError`, later `ConfigError`, `HandlerError`), `db.ts` (`Db` = `Context.Service<Db, Kysely<DB>>`, `query(db, run)` = `Effect.tryPromise` mapping to `DatabaseError`), `run.ts` (`runPromise`/`runSync` via `Effect.runPromiseExit`/`runSyncExit`, on failure throw `unwrap(Cause.squash(cause))` so the **original** thrown value reaches callers: Postgres error-code checks and the global exception filter behave identically).
4. Reference conversion by hand: `system-metadata.repository.ts`. Each repository file now exports an Effect service (`Context.Service` with `make(deps)` using `Effect.fn('X.method')` and a `static layer`) plus the original `@Injectable()` class as a thin Promise adapter with the **same constructor, methods, return types and decorators**. This keeps `test/medium.factory.ts` (`new key(db)`), `test/repositories/*.mock.ts` and all unit specs untouched. Pattern is written down for agents in `agent-patterns/effect-repositories.md` (in the repo).
5. Fan out to 7 subagents with disjoint file sets (simple Kysely repos; asset+asset-job; domain repos; map/search/sync/integrity/plugin; IO/library repos; config/logging/telemetry/process; event/job/websocket/cron/database). Told them not to touch registries, `base.service.ts`, `app.module.ts`, tests, and to avoid state-changing git commands since they share one working tree.
6. Mid-flight correction sent to all agents: adding `private effect` to a class that had **no** private members breaks specs that assign `Mocked<RepositoryInterface<X>>` to `X` (seen in `logging.repository.spec.ts`, `database-backup.service.spec.ts`; the tsc error lands in spec files, not the repository file, so per-file `tsc | grep` misses it). Fix: module-level singleton or lazily created optional field.
7. After all agents reported: renamed the 54 Effect services from `<Name>Service` to `<Name>Repo` because they collided with the Nest services in `src/services/` (AlbumService, UserService, TagService, ...). Mechanical regex within `src/repositories/*.ts`, then prettier.

## Gotchas / dead ends

- `rtk` swallows `vitest` output (`[RTK:PASSTHROUGH] ... parsing tiers failed`); read `server/.vitest/json/output.json` instead (delete `server/.vitest/` afterwards). `rtk grep` rejects `grep -ln`; use python/`git grep` for ad-hoc searches.
- Hand-writing service interfaces for Kysely queries is impractical; agents used `Context.Service<X, ReturnType<typeof makeX>>` with a module-level `makeX(db)`.
- Behavior shifts accepted: methods that threw synchronously before returning a Promise now reject (`JobRepository.pause/resume/empty/clear` with missing queue token, `MediaRepository.transcode` twoPass+stream output, email methods); the unused `telemetry.repository.wrap.duration` histogram is no longer created.
- Partially converted, deliberate: `plugin.load/callMethod`, `map.init` + geodata import, `websocket` gateway hooks, `telemetry` prototype wrapping, `database.withLock` internals (kept `AsyncLock` ordering), `storage.watchDir`.
- `DatabaseRepository` still bootstraps vector/vchord extensions on purpose (old migrations create them).
