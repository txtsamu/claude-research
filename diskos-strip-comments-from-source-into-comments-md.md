# diskOS: strip every code comment into `comments.md`, and keep it that way

Request: "cleanup comments inside our codebase, move them to `comments.md`, and from now on no comments in the codebase — add that instruction to the codebase". Repo `~/diskos/diskos`, branch `dev`, tip `be32bbc` before the change. Result: 253 files lost 8,431 comments (about 12k lines), all of it recorded in `comments.md` at the repo root. The changes are in the working tree, not committed.

The tools are in [`diskos-strip-comments/`](diskos-strip-comments/): `strip_comments.py` (strip and report), `verify.py` (per-language equality against `HEAD`), `anchor_scan2.py` (tests quoting removed text).

## Scope decisions (the user did not specify these)

- **Kept**: shebang lines; SPDX / copyright / licence blocks (legal notice, and REUSE-style headers); comments a tool reads: `# noqa: E402` (4 test files), `/* NOLINT */` (`ui/art.c`), `/* fall through */` (`ui/theme_kits.c`, GCC `-Wimplicit-fallthrough` reads it; clang ignores it), `# shellcheck disable=SC2046`.
- **Not touched**: vendored code (`ui/lvgl`, `ui/third_party`, `src/usbboot`, `spl-src`, `corresponding-source`, `licenses`, `ui/sqlite3.[ch]`, `ui/jsmn.h`, `ui/md5.c`, `ui/lv_conf.h` (LVGL's own template docs), `ui/tools/stb_image.h`); generated files (`ui/font_*.c` from lv_font_conv, `ui/i18n_tables.c`, `ui/theme_presets.inc`, `ui/theme_fonts.h`: the `tools/gen_*.py` generators are stripped, but their outputs keep the `GENERATED by` line so `gen_theme_presets.py --check` still passes); binaries; Markdown/text docs; config/data (`.gitignore`, YAML, JSON, lock).
- **Python docstrings are not comments**: left alone (306 docstrings, 67 files). Offer to move them too.

## Steps

1. Candidate list = tracked files minus vendored trees, minus binaries (NUL byte test), minus docs:
   `git ls-files | grep -vE '^(ui/lvgl/|ui/third_party/|corresponding-source/|licenses/|spl-src/|docs/|src/usbboot/|...)' | grep -vE '\.(png|webp|bin|md|txt|json|yml|...)$'`
   Binary files named without an extension (`payload/mq_ui`, `payload/dropbearmulti`) only show up as binary by content, so test for NUL, not for the name.
2. One scanner per language, because a regex cannot tell a comment from a string:
   - C/H/inc/rc: state machine over `//` (with backslash continuation), `/* */`, string and char literals. A `'` with no closing quote within ~12 chars is treated as a plain character (`#error don't`).
   - `.ld`, `.S`, CSS: block comments only. JS: `//`, `/* */`, strings, template literals, regex-vs-division by previous token. HTML: `<!-- -->` plus the contents of `<script>`/`<style>`. XML manifest: `<!-- -->`. PowerShell: `<# #>`, `#` at token start, here-strings.
   - Python: `tokenize` COMMENT tokens (exact).
   - Shell (also extensionless scripts, found by shebang): `#` is a comment only at word start; skips `'..'`, `".."` with nested `$(..)`, `${..}`, backticks, `$'..'`, and heredoc bodies (heredoc text is data).
   - Makefile: non-recipe lines take the first unescaped `#`; recipe lines (leading tab) are scanned as shell.
3. Each comment is replaced by a sentinel (`U+E000 id U+E001`), then a line pass drops comment-only lines, trims the blanks before trailing comments, and collapses blank lines the removal left behind. Line numbers in `comments.md` are measured on the final text: the sentinel's line, or the next kept line for a removed whole line.
4. `comments.md` entry = `**L<n>** \`<code on that line>\`` plus the comment text in a `~~~text` fence (`/* */` stars and `//` `#` prefixes removed, indentation dedented). The code snippet is there so the anchor survives later edits.
5. Dry run first (`--md` only), then `--apply`. Tree was clean (`git status`), so `git checkout .` was the undo.
6. `python3 verify.py . list.txt` compares every changed file against `git show HEAD:<file>`:
   - `.py`: `ast.dump` equal.
   - shell: `bash --pretty-print` equal after dropping blank lines (bash 5 prints the parsed script without comments).
   - C: `clang -E -P` token stream equal; digits masked so `__LINE__` in `assert` does not matter; compile from the same relative path in both trees or `__FILE__` differs.
   - Makefile: `/usr/bin/make -pnq -R -C <dir> -f <same temp path for both>` database equal. Use `/usr/bin/make`: the `rtk` wrapper appends a `[full output: ...tee/<timestamp>.log]` line that differs on every run. Only difference found: trailing blanks before a removed `#` in variable values (make keeps them as part of the value); harmless.
   - second pass of the stripper finds nothing left.

## What broke and how it was fixed (nothing here was a compile problem)

- **Tests anchored on comment text** (found by running every suite, then by `anchor_scan2.py`, which lists test string literals that were in a changed file at `HEAD` and are in none of them now):
  - `ui/tests/boot_probe_test.py`: the `PDEATH` anchor line included a trailing comment. Fixed to the bare statement.
  - `tests/test_windows_cli.py`: the expected PowerShell block included `# NUL disables all pip config files...`. Line removed from the expected text.
  - `tests/test_boot_select.py` + `tests/test_sd_guards.py` sliced `payload/S97diskos_install` between `# >>> SUPERVISOR BEGIN` and `# <<< SUPERVISOR END` (the comment said "keep them"). They now slice from `if [ "$1" != "__worker" ]; then` to the first line of `SIGS="TERM HUP INT`.
- **A script embedded twice**: `ui/rmguard.c` holds `payload/diskos-rmguard` as a C string (`RMGUARD_SCRIPT`), and `ui/tests/rmguard_test.py` compares the bytes. Stripping only the payload made 8 subtests fail. The 13 `"#...\n"` comment lines were removed from the C literal as well, so the pair stays identical. Side effect: `mq_ui` `.text` is 1,200 bytes smaller (1,196 bytes of script plus padding); the flashed Disc image still carries the old guard, and the UI then publishes its own fallback copy, which is the designed path.
- `ui/tools/generate_i18n.py --help` has no argparse: it wrote a file named `--help` into the repo root. Deleted. Do not probe generators with `--help`.
- Podman on Fedora: `Permission denied` stat'ing `Makefile` in the bind mount until `--security-opt label=disable` was added.
- The `rtk` hook rewrites `make`, `grep`, `diff` and `case ... ;;` one-liners; use `/usr/bin/<tool>` or script files when exact output matters.

## Test results

- `make -C ui/tests CC=clang check` (needs a `cc`->`clang` shim on PATH for the Python tests): passes.
- `python3 -I -m unittest discover -s tests -p 'test_*.py'` (no pytest on this box): the same 2 failures and 8 errors as an unmodified `HEAD` worktree (compared test-ID by test-ID with `comm`); 156 skipped (Windows/macOS only, covered by `anchor_scan2.py`, not by running them).
- Cross build: `podman run --rm --userns=keep-id --security-opt label=disable -v "$PWD/ui:/src" -w /src localhost/diskos-ui-builder:latest sh -c 'make clean >/dev/null 2>&1; make -j4 CROSS=$CROSS EXTRA_CFLAGS=-DDISKOS_TEST_OUTPUTS'`. Before the `rmguard.c` edit, the rebuilt `ui/mq_ui` had the same md5 as the binary flashed that morning (`d7cbfd0d5737299d0272f4d903f034be`): proof the C/H strip changed no compiled byte. After it, only the guard text differs (`size`: data and bss identical).

## Keeping it that way

Added the rule "No comments in source" to `agents/AGENTS.md`, a numbered ground rule in `CONTRIBUTING.md`, and a root `CLAUDE.md` (Claude Code reads that, not `AGENTS.md`): explanations go to `comments.md` under the file's heading or `docs/`; allowed exceptions as listed above; never key a test on comment text; an embedded copy of a script must stay identical in both places.
